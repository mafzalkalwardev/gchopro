## Decisions

- 2026-11-25 — Milestone issues M1–M8, blocked in order, instead of a tracer-bullet breakdown. GChoPro-PRD.md §24 is the approved split.
- 2026-11-25 — `.env.example` adds `POSTGRES_PASSWORD`, `GCHOPRO_APP_PASSWORD`, and `REDIS_PASSWORD` for Compose. They must match the database and Redis URLs. The apps do not read them.
- 2026-11-25 — `infra/postgres/init-roles.sh` creates `gchopro_app` because the Postgres image does not expand env vars in `.sql` files. `init-roles.sql` documents that and creates `citext`.
- 2026-11-25 — Table grants live in `packages/db/src/sql/grants.sql` and run at the end of `pnpm db:migrate`. Initdb runs before the tables exist.
- 2026-11-25 — In local Compose, `gchopro_owner` is the image superuser. Least privilege for `gchopro_app` is still applied. Production hardening is M8.
- 2026-11-25 — `stats_daily.user_scope_id` is a stored generated column, `coalesce(user_id, nil uuid)`, so the primary key can include that expression.
- 2026-11-25 — Shared template names use a unique index on `coalesce(owner_user_id, nil uuid), name`, because Postgres unique constraints do not treat NULL owners as equal.
- 2026-11-25 — The minimum gap floor stays in `settings`. It is not a cross-table check. Core enforces it in a later milestone.
- 2026-11-25 — `audit_logs.id` is `bigint GENERATED BY DEFAULT AS IDENTITY`. That is Drizzle's equivalent of `bigserial`.
- 2026-11-25 — Seed field encryption lived in `packages/db/src/field-crypto.ts` for M0. M1 moved it to `packages/core/src/crypto/field.ts`. Dev rows are ciphertext, not plaintext.
- 2026-11-25 — "Very conservative" copies segment, group, and window fields from the default policy. The PRD only overrides gap and the three rate caps.
- 2026-11-25 — `demo2` is a 2-day plan so `ends_at` is two days out. Seed month math uses a fixed Asia/Karachi offset of +5. General timezone math is M3.
- 2026-11-25 — Dev sample peers are `+15005550001` and `+15005550002`. The seeded opt-out is `+15005550006`.
- 2026-11-25 — Dev token and demo passwords print only on a TTY. CI logs stay free of those values.
- 2026-11-25 — `robots.ts` on the admin and portal shells returns `Disallow: /`, from §18.7. There is no `/healthz` until M8.
- 2026-11-25 — Docker image tags are pinned by the digest resolved from the registry on this date.
- 2026-11-25 — `drizzle-orm` is `^0.45.2` because `0.44.x` is in GHSA-gpj5-g38j-94v9. `postcss` is overridden to `^8.5.18` because Next's copy is in GHSA-6g55-p6wh-862q and GHSA-r28c-9q8g-f849.
- 2026-11-25 — Zod is `^4.6.6`, not Zod 3. GHSA-mrhx-c7xc-m3w5 marks every release before 4.6.6 high, and §18.13 fails the build on high. M0 only uses object, string, enum, and preprocess schemas.
- 2026-11-25 — Next `output: "standalone"` is off when `process.platform` is `win32`. The standalone file tracer recreates pnpm symlinks, and this machine returns EPERM. CI on Ubuntu still builds standalone.
- 2026-11-26 — A password change keeps the current session by setting that session's `created_at` to the new `password_changed_at`. The §11 check rejects every session created before the password change, including the one that submitted it, unless that timestamp moves with the change.
- 2026-11-26 — `SEED_DEMO_PASSWORD` is optional and read only by the development seed. CI sets it so the portal login test has a known password. It is not required to boot the apps.
- 2026-11-26 — Admin and portal documents are rendered per request. The CSP nonce has to be minted for that request, or `strict-dynamic` blocks the scripts.
- 2026-11-26 — `devices.slots_on_device` and `devices.rotate_requested` are stored columns. Capacity and a forced token rotation need them, and §6.3 did not list either field.
- 2026-11-26 — Part reports live in `message_part_reports`. Idempotency is `(message_id, event, part_index)`.
- 2026-11-26 — A handset is online when its last heartbeat is within `health.offline_after_seconds` (seeded at 90). `error` still waits until the heartbeat is 10 minutes old.
- 2026-11-26 — Device routes answer with the §9 body. Admin routes keep the §10 `{ data }` envelope. Device calls use the bearer token. They do not use the browser CSRF cookie.
- 2026-11-26 — A wrong pairing code increments the attempt count only when one pairing is open. Several open pairings stay untouched, so one guess cannot burn every code.
- 2026-11-26 — A blank device number is not a SIM identity. Re-reporting a retired number reopens that SIM row so the phone hash can stay unique.
- 2026-11-26 — Re-test creates a queued `is_retest` message. Nothing sends it until the M4 worker exists. Opt-out confirmation, translation, and email or Telegram alerts stay in later milestones.
- 2026-11-26 — An inbox row with no assigned user is counted unroutable and stored as an alert. `messages.user_id` cannot be null, so there is no unroutable message row.
- 2026-11-26 — `message.received` is not published on the portal session channel. That channel currently treats every payload as a revoked session.
- 2026-11-26 — SIM health marks use ink and signal. The screen spec's extra hues stay out of the theme.
- 2026-11-26 — The gateway application id is `com.gchopro.gateway`. A real dual-SIM phone still has to be checked by hand. CI runs `assembleDebug` and the JVM unit tests.
- 2026-11-26 — Subscription periods use `date-fns` v4 and `@date-fns/tz`. `date-fns-tz` targets date-fns v3.
- 2026-11-26 — `subscriptions:tick` runs every 60 seconds inside the worker process. BullMQ repeatable jobs stay in M4.
- 2026-11-26 — Usage gauges stay at zero until message counters exist. `PATCH` does not change `simId`; assignment stays on its own route so the session revocation still happens.
- 2026-11-26 — Unassigning a SIM cancels that user's queued, scheduled, and held messages on the old SIM. Disabling a user or blocking a subscription moves queued and held messages to `blocked`. A read-only expiry blocks those messages and keeps the session.
- 2026-11-26 — The API returns a password only when it generated one. The three-day reminder is an in-portal notice. The daily expiring alert is stored and not emailed. Both email and the support view stay in later milestones.
- 2026-11-26 — `sendingBlocked` is the gate for read-only and scheduled access. The send route is M4 and has to call it. Payment CSV cells escape formula characters.
- 2026-11-26 — M4 publishes `message.status` and `message.received` on `user:{id}` with a `type` field. A payload without `type` stays `session.revoked`, so the existing revoke listener is unchanged.
- 2026-11-26 — Gate order, gap, window, and retries are pure functions in core. Fake timers cover them. The worker calls the same dispatch function. CI does not start the worker process.
- 2026-11-26 — The worker keeps the 60-second subscription tick. A 2-second pump promotes scheduled messages, sweeps leases, and feeds one BullMQ queue per SIM (`send:sim:{id}`, concurrency 1). The kill switch is polled every 500 ms. Translate, notify, health, stats, retention, and backup jobs stay in later milestones.
- 2026-11-26 — BullMQ uses its own Redis connection with `maxRetriesPerRequest: null`. The shared client stays at 2.
- 2026-11-26 — Outbound translation holds a message only when a provider other than `none` is configured. The default provider is `none`, so a user with translation turned on still sends. Provider calls are M6.
- 2026-11-26 — One message is in flight per SIM because dispatch checks for an unexpired lease. The job does not block until the handset reports.
- 2026-11-26 — Cap counters live in Redis and increment only at dispatch. Portal usage gauges read those keys. A segment cap holds as `rate_segments`. A rejected cap blocks as `limit_reached`.
- 2026-11-26 — A retry never changes `sim_id`. A suspended SIM's messages stay on that queue.
- 2026-11-26 — Portal `/` is the inbox and keeps `signed-in`, `user-id`, and the session watch. Admin `/` is the dashboard and keeps `signed-in`. Settings links to the password page and the CSV export. Theme and language catalogs stay in M7.
- 2026-11-26 — The pacing purpose sentence is in the gate module and on the policies screen: "Pacing and limits keep each SIM within carrier fair-use policies and protect deliverability. They are not a mechanism to disguise traffic or evade carrier controls."
- 2026-11-25 — A keyword matches after NFKC and lowercasing when it is the whole message or a prefix followed by whitespace or punctuation. Opt-in is checked first and reverses only `source=keyword` rows. STOPPING and a keyword buried in a sentence do not match.
- 2026-11-25 — A new keyword opt-out cancels queued, held, and scheduled messages to that number, then queues one confirmation with `is_opt_out_confirmation`. That flag skips only the opt-out gate. An admin opt-out is reversed only by an admin, with sudo, a reason, and evidence.
- 2026-11-25 — `suspected_suspended` does not set `paused_by_admin`. The queue pauses because the SIM is not assignable, and pending rows stay on that SIM as `held` / `sim_unhealthy`. A failed re-test leaves the state. A successful re-test returns the SIM to `active` and requeues those rows.
- 2026-11-25 — The worker sweeps device alerts and delivers pending notifications every 30 seconds. CI does not start the worker. Tests inject the mail and Telegram transport. Alert text is the title and type only. A critical alert can be sent again after 60 minutes. A warning is sent once.
- 2026-11-25 — Re-test numbers are `ADMIN_TEST_NUMBERS` plus `settings.test_numbers`. Email is sent only when `SMTP_HOST` and `SMTP_FROM` are set. Telegram uses `TELEGRAM_BOT_TOKEN`.
- 2026-11-25 — The §19.4 policy sentence is in the admin and portal footers. Translation providers, analytics, and retention purge stay in later milestones.
